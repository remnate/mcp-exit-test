# Release announcement

MCP Exit Test 0.1 brings a process-lifetime check to Linux CI. Give a headless Codex thread three configuration reconnects, then close the host. A registered stdio fixture identifies the connection that answered each call. The report shows when the old server and its tagged child disappeared. A deliberate survivor gives maintainers a failing JUnit case to try before adding the clean check to their pipeline. The [checkout demo](../README.md) works without a Python package registry release.

## Pilot plan

Invite four host maintainers, three SDK or integration maintainers and three stdio-server authors in their testing forums. Start each pilot by asking who owns the server, who owns the child and when each must retire. Offer a removable strict CI job and ask participants to review the clean and survivor artifacts on their own integration.

With consent, publish a reusable CI example for each accepted configuration. Count distinct people who run or review results on their own integration toward a target of 100. Track whether another host can adopt the same reconnect scenario and ownership rules. If ten pilots yield no second host willing to retain the check, offer the scenario upstream to the first host and stop expanding the matrix.
